### Story

*As a Crawler Agent, I want to use a local AI model to extract content and images from a destination page, so that I can gather the required data in a structured format.*

### Acceptance Criteria

1.  The application configures `Crawl4AI`'s `LLMExtractionStrategy` to connect to a local `Ollama` provider.
2.  The strategy is provided with the Pydantic schema defined in Story 1.2.
3.  Given the HTML of a destination page, the agent successfully populates the Pydantic model with the extracted data.
4.  The populated Pydantic model is logged to the console for verification.

### Dev Notes

*   **AI Strategy:** The core of this story is the `Crawl4AI.LLMExtractionStrategy`. This will be configured to point to the local Ollama service. *(Source: docs/architecture.md#2-technology-stack)*
*   **Schema Driven Extraction:** The Pydantic model `ScrapedData` from `src/database/models.py` is critical. It will be passed to the strategy to ensure the LLM returns data in the correct, validated format. *(Source: docs/architecture.md#4-data-models-and-schema)*
*   **Integration:** The extraction strategy is not run separately; it is passed directly into the `crawler.arun()` method. The crawler handles the orchestration of navigation and extraction. *(Source: Story 1.5 Implementation Plan)*

### Tasks / Subtasks

1.  **(AC: 1)** Update `config/config.yaml` to include an `ollama` section specifying the model name.
2.  **(AC: 1, 2)** Create `src/core/extractor.py` and a function that is responsible for creating and configuring the `LLMExtractionStrategy` instance.
3.  **(AC: 1, 2)** Refactor the `_navigate_to_destination` function in `crawler.py` to create the `LLMExtractionStrategy` and pass it to the `crawler.arun()` call.
4.  **(AC: 3, 4)** After the `arun()` call, process the `result.extracted_content` by validating it with the `ScrapedData.model_validate_json` method and log the result.
